# 选题池

公众号定位：**AI 前沿的通俗解读**。三个栏目循环，三天一轮——

- **A 论文解读**：AI 顶会的全领域最新论文，**不再限于具身智能**。视觉、语言与多模态、生成模型、强化学习与智能体、AI for Science 都算
- **B 项目介绍**：GitHub 上近期热门的 AI 开源项目
- **C 科技新闻**：科技圈正在发生的事。讲事件，不讲论文也不讲仓库

选题标准：

- 论文 / 项目——**能用一句话讲清它在解决什么真实问题**
- 新闻——**能用一句话讲清它为什么值得普通人关心**

## 轮换规则

严格 **A → B → C** 循环。定下一期前，先看「已发布」表格最后一条的「类型」列，往后推一格。每天一篇，不分工作日和周末。

论文类的方向按周轮换，避免连续同质：视觉 → 语言与多模态 → 生成模型 → 强化学习与智能体 → AI for Science，一周一换。

## 经验沉淀

**标题**：带具体动作或数字的比抽象概念好。"穿过一堆杂物"胜过"全身视觉语言导航"。

**结构**：场景开头 → 旧方法的局限 → 这篇怎么改的 → 数据和训练怎么来 → 结果 → 反直觉发现 → 局限 → 收尾。这个骨架读者反馈最好。

**配图**：论文原图负责"可信"，自制示意图负责"看懂"。一张自制图讲清一个机制，别塞三个。

**数字**：所有数字必须有出处。不确定就写"论文未提及"，不要圆。

**长度**：2500 字左右最舒服，超过 3500 字完读率明显下降。

**篇幅硬限制**：微信 `draft/add` 的 content 字段上限 2 万字符，而每个 `<p>` 带约 100 字符的行内样式。论文类模板的四个组件（导语卡、档案卡、链接块、图注）本身要吃掉 1500–2000 字符，所以 2600 汉字配 6 张图约 1.9 万字符，已经没有余量。超了按此顺序处理：合并相邻短段（省 100 字符/段）→ 删次要图 → 拆篇。

**字符数不是免费的**：11-16 那篇改完新排版直接冲到 2.16 万，超了 800。最后把正文 `<p>` 的 `letter-spacing` 删掉（每段省 18 字符 ×93 段）才压回 1.9 万。以后加任何新组件，都先跑一次 `--dry-run` 看「正文长度」这一行。

**栏目**：2026-11-16 起改为论文（A）/ 项目（B）/ 新闻（C）三段循环。历史：论文（TANGO）→ 项目（StarVLA）→ 论文（Rho）→ 项目（RPent）→ 论文（Ψ₀）→ 项目（Microduck）→ 论文（ABot-M0）→ 项目（Jumper）→ 论文（VT-WM）→ 项目（gpu-unlock）→ 论文（RoboColosseum）→ 项目（HALO）→ 论文（GAP）→ 项目（RoboScript）→ 论文（BEHAVIOR 2026）→ 项目（unslop）→ 论文（PEAR）。11-16 是 A 类，下一篇为 B 类项目。

**「同一场景、只换指令」是最省力的科普角度**：π0.5 在原题上 96.9%，换成另一个任务掉到 0.75%。这个反差不需要任何背景知识就能看懂，比讲架构好一百倍。凡遇到「泛化」类论文，先找这类「换个条件就崩」的对照实验。

**论文里没写的具体例子一律不编**：初稿想写「把碗放到盘子上 / 放到灶台上」，但原文只写「a different task in the same scene」，具体是哪个碗哪个灶台是二手报道里的细节。改成「同一间屋子、同一个摆位、只把指令换成另一件事」，信息量没少，风险归零。

**「没有 XX 模块」这类否定句要给出读者能想象的对立面**：论文写 no perception tools / no grasp planner / no skill library，小白不知道这三个东西平时起什么作用。必须补一句「没有谁事先告诉它东西在哪、该从上面抓」，否则这句只是空话。

**「官方开源 + 论文」是最好的项目选题**：HALO 这类仓库自带 arXiv，论文原图负责可信、README 负责"到底开源了什么"，两类素材都有。比纯仓库稿好写，比纯论文稿好找图。

**代码开源 ≠ 能复现**：先翻 README 的「Weights and data」段和残留的 `TODO(release)` 注释。HALO 明确写"没有训练好的生成器检查点，也没有数据集"，这句话直接撑起整段局限，比任何客套话都有说服力。

**二手数字只用来判断热度，不用来写稿**：中文媒体把 91% 转得到处都是，但"链式任务 70%/50%""5 次失败 3 次头转开"这些只有原文有，也是全文最有价值的部分。热度看媒体，数字看原文。

**标题落在"第一次"上最容易懂**：「没见过一间真房子，它就自己找了张椅子坐下」比"零样本全身运动迁移"好一百倍。


**预印本要标清楚**：VT-WM 只有 arXiv 版 + OpenReview 投稿记录，项目页与论文都没写录用会议。正文用「状态：预印本」如实交代，别为了贴「顶会论文」栏目硬安一个会议。

**相对涨幅 vs 百分点**：论文爱写 "up to 35% higher"，实际是 69%→93% 的相对涨幅，绝对差 24 个百分点。这类地方必须拆开讲，否则读者会算出 104%。

**项目稿的局限好写**：成熟仓库基本都会在 PROJECT_GUIDE / README 的 status 段里自陈"哪一步还没做完"，直接引用比论文的局限段省事，也更容易写出信任感。

**"只迁移改法"是很好的科普角度**：GAP 不搬"怎么弹"，只搬"偏了往哪边拧"。这类"换掉迁移对象"的思路，比讲架构好讲得多，读者也能直接类比到自己的学习经验（教练纠正的不是动作本身，而是偏差方向）。

**arXiv HTML 的数字会被 LaTeX 复制成"1616""3.33"...**：`1616 actuated finger joints` 其实是 16，`4.44.4` 其实是 4.4，`77 min` 其实是 7 min。读到相邻重复的数字要警惕，别照抄。

**"相对提升"必须当场换算**：GAP 真机写 +16%/23%/3.6%，全是相对自己；0.759 涨 23% 是 0.935，绝对差 17.6 个点。不换算，读者会算成 0.98。

**arXiv 没生成 HTML 版时，从 PDF 取图**：RoboScript 的 `/html/2611.12885v1` 返回 404（No HTML for the source），但 PDF 里的图是矢量+位图混排。用 pymupdf `get_pixmap(clip=Rect(...), dpi=210)` 按坐标裁切，图内文字 1:1 清晰，比截图干净，也不会有缩放糊边。

**密集信息图要按面板拆**：Fig. 1 整幅 1395×643，压到手机 390 宽后字全糊；只取右半的 (c) 榜单面板（630×694）后，每一行的数字都能读。判据是「裁完的宽高比接近 2:3 或 1:1」而不是 2.2:1 的横条。

**「仓库 + 论文」是项目稿最优解，但热度要如实交代**：本次仓库 1 周 67 星，不算爆款，热度只靠「arXiv 当日新稿 + 第三方转载」。这类选题可以写，但汇报时必须说明「不热」，别把冷门说成热门。

**compare 图的 note 会与图注重复**：图底部的小字说明和正文图注写的是同一句话，删掉 note 只留图注，观感更干净。

**「名次掉了、分数涨了」是极好的科普角度**：榜单名次是相对的，题目变难、对手变强都会让名次下滑。写这类稿必须把「名次」和「水平」拆成两件事讲，否则读者会误读成退步。BEHAVIOR 2026 那篇正是靠这个反差立住的。

**挑战赛稿要先确认是哪一名**：标题写 "Our Solution for the 2026 XXX Challenge" 很可能是第 9 名而不是冠军。BEHAVIOR 2026 这篇摘要第一句就是 "We placed 9th"，差点按冠军事写。凡涉及名次，先在 abs 页搜 "place" / "rank"。

**同一篇里要区分「哪个模型」的分数**：BEHAVIOR 稿里 0.392 是纯学习策略，0.446 是含 14 件外包的公开提交，27.3% 又是后者口径。混着写读者会算不明白，必须在句子里点明主体。

**定性判断也要对着图表核**：初稿写「爆米花是最简单的一档任务」，但 Figure 11 里它排在中上，最简单的其实是「捡垃圾」和「装调制解调器」。难度这种形容词最容易凭感觉写错。

**「AI 味」这类软话题也能写成硬稿**：unslop 没有跑分、没有数据集，全靠一份 78 条的征兆清单和 9 道工序撑起可信度。写这类项目，重点不是"它多神"，而是把规则一条条摊开让读者自己判断。栏目定位里的「AI 项目」不限于模型，给 AI 用的 skill 也算。

**清单类项目要给出条目数**：78 条、11 组、9 道工序、18 条自检，这几个数字让"很细"从形容词变成事实。数之前先跑脚本数，别估。

**推送前先花 2 秒验证白名单**：调一次 `cgi-bin/token`，能拿到 token 就说明白名单正常，再去推正文。40164 只跟调用方 IP 有关，跟稿件、封面、AppSecret 都无关，别在稿子上白折腾。本机是移动动态 NAT，出口 IP 会变（11-10~11-13 是 117.185.175.186，11-15 起是 117.185.173.213），白名单只认精确 IPv4、不认网段，长期稳定要换固定公网 IP 的机器。

**新闻类的三条硬规矩**（2026-11-16 新增）：

1. **两个以上独立信源**才能写进正文。厂商单方面说法要标「这是他们自己的说法」，不能当事实。
2. **数字回一手原文核**。中文媒体的「暴涨 300%」「节省 90% 成本」几乎都缺口径，查不到出处就写「官方未公布具体数字」。
3. **不做预测、不替读者判断股价**。新闻稿的结论只能是「这件事改变了什么」，不是「所以某某要涨」。

**新闻类的结构跟论文不一样**：论文从场景切入，新闻从「刚发生的那个动作」切入（谁在什么时候发布了什么）。然后按「发生了什么 → 为什么现在发生 → 对普通人意味着什么 → 还没确认的部分」四段走。不要写成时间线大事记。

**新闻选题的价值判断**：问自己「这条消息三个月后还有意义吗」。只有当天热度、没有结构性变化的（比如某榜单换了个名次），不写。

**论文类放开到全领域后，选题门槛反而更高**：不是「顶会」就写，而是「现象能否被一张对比图说清」。视觉、多模态类论文的图通常比具身智能更好看，但也更容易变成炫技演示。判据：能不能在开头 300 字内讲出让非从业者「哦原来是这样」的反差。

**跨领域术语要现查现解释**：具身智能领域的术语我已经很熟，但语言模型、扩散生成、AI for Science 里的 MoE、RLHF、上下文窗口、蒸馏、量化等，每个都得给生活化类比，别直接搬论文原话。
