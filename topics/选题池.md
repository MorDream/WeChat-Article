# 选题池

公众号定位：**AI 前沿的通俗解读**。三个栏目循环，三天一轮——

- **A 论文解读**：AI 顶会的全领域最新论文，**不再限于具身智能**。视觉、语言与多模态、生成模型、强化学习与智能体、AI for Science 都算
- **B 项目介绍**：GitHub 上近期热门的 AI 开源项目
- **C 科技新闻**：科技圈正在发生的事。讲事件，不讲论文也不讲仓库

选题标准：

- 论文 / 项目——**能用一句话讲清它在解决什么真实问题**
- 新闻——**能用一句话讲清它为什么值得普通人关心**

## 轮换规则

严格 **A → B → C** 循环。定下一期前，先看「已发布」表格最后一条的「类型」列，往后推一格。每天一篇，不分工作日和周末。

论文类的方向按周轮换，避免连续同质：视觉 → 语言与多模态 → 生成模型 → 强化学习与智能体 → AI for Science，一周一换。

## 经验沉淀

**标题**：带具体动作或数字的比抽象概念好。"穿过一堆杂物"胜过"全身视觉语言导航"。

**结构**：场景开头 → 旧方法的局限 → 这篇怎么改的 → 数据和训练怎么来 → 结果 → 反直觉发现 → 局限 → 收尾。这个骨架读者反馈最好。

**配图**：论文原图负责"可信"，自制示意图负责"看懂"。一张自制图讲清一个机制，别塞三个。

**数字**：所有数字必须有出处。不确定就写"论文未提及"，不要圆。

**长度**：2500 字左右最舒服，超过 3500 字完读率明显下降。

**篇幅硬限制**：微信 `draft/add` 的 content 字段上限 2 万字符，而每个 `<p>` 自带约 80 字符的行内样式（加上标签本身约 91）。导语卡、档案卡、链接块、图注这套组件要吃掉 1500–2000 字符，所以 2600 汉字配 6 张图大约 1.9 万字符，余量只有几百。**目标线定在 1.95 万以下**。超了按此顺序处理：合并相邻短段（省 90 字符/段）→ 删次要图 → 拆篇。不要去改组件样式，那是三类共用的代码。

**字符数不是免费的**：11-16 那篇改完新排版直接冲到 2.16 万，超了 800。最后把正文 `<p>` 的 `letter-spacing` 删掉（每段省 18 字符 ×93 段）才压回 1.9 万。以后加任何新组件，都先跑一次 `--dry-run` 看「正文长度」这一行。

**栏目**：2026-11-16 起改为论文（A）/ 项目（B）/ 新闻（C）三段循环。历史：论文（TANGO）→ 项目（StarVLA）→ 论文（Rho）→ 项目（RPent）→ 论文（Ψ₀）→ 项目（Microduck）→ 论文（ABot-M0）→ 项目（Jumper）→ 论文（VT-WM）→ 项目（gpu-unlock）→ 论文（RoboColosseum）→ 项目（HALO）→ 论文（GAP）→ 项目（RoboScript）→ 论文（BEHAVIOR 2026）→ 项目（unslop）→ 论文（PEAR）→ 项目（laya）→ 新闻（ChatGPT 钱包）。11-17 发了 B、C 两篇（上午项目、中午新闻）。11-18 A 类论文（Know When to Zoom）→ 11-19 B 类项目（Mika）→ 11-20 C 类新闻（Anthropic 上市）→ 11-21 A 类论文（作者归属）→ 11-22 B 类项目（Craft Anything）→ 11-23 A 类论文（决策模型三种角色，方向为强化学习与智能体），下一篇为 B 类项目。

**「同一场景、只换指令」是最省力的科普角度**：π0.5 在原题上 96.9%，换成另一个任务掉到 0.75%。这个反差不需要任何背景知识就能看懂，比讲架构好一百倍。凡遇到「泛化」类论文，先找这类「换个条件就崩」的对照实验。

**论文里没写的具体例子一律不编**：初稿想写「把碗放到盘子上 / 放到灶台上」，但原文只写「a different task in the same scene」，具体是哪个碗哪个灶台是二手报道里的细节。改成「同一间屋子、同一个摆位、只把指令换成另一件事」，信息量没少，风险归零。

**「没有 XX 模块」这类否定句要给出读者能想象的对立面**：论文写 no perception tools / no grasp planner / no skill library，小白不知道这三个东西平时起什么作用。必须补一句「没有谁事先告诉它东西在哪、该从上面抓」，否则这句只是空话。

**「官方开源 + 论文」是最好的项目选题**：HALO 这类仓库自带 arXiv，论文原图负责可信、README 负责"到底开源了什么"，两类素材都有。比纯仓库稿好写，比纯论文稿好找图。

**代码开源 ≠ 能复现**：先翻 README 的「Weights and data」段和残留的 `TODO(release)` 注释。HALO 明确写"没有训练好的生成器检查点，也没有数据集"，这句话直接撑起整段局限，比任何客套话都有说服力。

**二手数字只用来判断热度，不用来写稿**：中文媒体把 91% 转得到处都是，但"链式任务 70%/50%""5 次失败 3 次头转开"这些只有原文有，也是全文最有价值的部分。热度看媒体，数字看原文。

**标题落在"第一次"上最容易懂**：「没见过一间真房子，它就自己找了张椅子坐下」比"零样本全身运动迁移"好一百倍。


**预印本要标清楚**：VT-WM 只有 arXiv 版 + OpenReview 投稿记录，项目页与论文都没写录用会议。正文用「状态：预印本」如实交代，别为了贴「顶会论文」栏目硬安一个会议。

**相对涨幅 vs 百分点**：论文爱写 "up to 35% higher"，实际是 69%→93% 的相对涨幅，绝对差 24 个百分点。这类地方必须拆开讲，否则读者会算出 104%。

**项目稿的局限好写**：成熟仓库基本都会在 PROJECT_GUIDE / README 的 status 段里自陈"哪一步还没做完"，直接引用比论文的局限段省事，也更容易写出信任感。

**"只迁移改法"是很好的科普角度**：GAP 不搬"怎么弹"，只搬"偏了往哪边拧"。这类"换掉迁移对象"的思路，比讲架构好讲得多，读者也能直接类比到自己的学习经验（教练纠正的不是动作本身，而是偏差方向）。

**arXiv HTML 的数字会被 LaTeX 复制成"1616""3.33"...**：`1616 actuated finger joints` 其实是 16，`4.44.4` 其实是 4.4，`77 min` 其实是 7 min。读到相邻重复的数字要警惕，别照抄。

**"相对提升"必须当场换算**：GAP 真机写 +16%/23%/3.6%，全是相对自己；0.759 涨 23% 是 0.935，绝对差 17.6 个点。不换算，读者会算成 0.98。

**arXiv 没生成 HTML 版时，从 PDF 取图**：RoboScript 的 `/html/2611.12885v1` 返回 404（No HTML for the source），但 PDF 里的图是矢量+位图混排。用 pymupdf `get_pixmap(clip=Rect(...), dpi=210)` 按坐标裁切，图内文字 1:1 清晰，比截图干净，也不会有缩放糊边。

**密集信息图要按面板拆**：Fig. 1 整幅 1395×643，压到手机 390 宽后字全糊；只取右半的 (c) 榜单面板（630×694）后，每一行的数字都能读。判据是「裁完的宽高比接近 2:3 或 1:1」而不是 2.2:1 的横条。

**「仓库 + 论文」是项目稿最优解，但热度要如实交代**：本次仓库 1 周 67 星，不算爆款，热度只靠「arXiv 当日新稿 + 第三方转载」。这类选题可以写，但汇报时必须说明「不热」，别把冷门说成热门。

**compare 图的 note 会与图注重复**：图底部的小字说明和正文图注写的是同一句话，删掉 note 只留图注，观感更干净。

**「名次掉了、分数涨了」是极好的科普角度**：榜单名次是相对的，题目变难、对手变强都会让名次下滑。写这类稿必须把「名次」和「水平」拆成两件事讲，否则读者会误读成退步。BEHAVIOR 2026 那篇正是靠这个反差立住的。

**挑战赛稿要先确认是哪一名**：标题写 "Our Solution for the 2026 XXX Challenge" 很可能是第 9 名而不是冠军。BEHAVIOR 2026 这篇摘要第一句就是 "We placed 9th"，差点按冠军事写。凡涉及名次，先在 abs 页搜 "place" / "rank"。

**同一篇里要区分「哪个模型」的分数**：BEHAVIOR 稿里 0.392 是纯学习策略，0.446 是含 14 件外包的公开提交，27.3% 又是后者口径。混着写读者会算不明白，必须在句子里点明主体。

**定性判断也要对着图表核**：初稿写「爆米花是最简单的一档任务」，但 Figure 11 里它排在中上，最简单的其实是「捡垃圾」和「装调制解调器」。难度这种形容词最容易凭感觉写错。

**「AI 味」这类软话题也能写成硬稿**：unslop 没有跑分、没有数据集，全靠一份 78 条的征兆清单和 9 道工序撑起可信度。写这类项目，重点不是"它多神"，而是把规则一条条摊开让读者自己判断。栏目定位里的「AI 项目」不限于模型，给 AI 用的 skill 也算。

**清单类项目要给出条目数**：78 条、11 组、9 道工序、18 条自检，这几个数字让"很细"从形容词变成事实。数之前先跑脚本数，别估。

**推送前先花 2 秒验证白名单**：调一次 `cgi-bin/token`，能拿到 token 就说明白名单正常，再去推正文。40164 只跟调用方 IP 有关，跟稿件、封面、AppSecret 都无关，别在稿子上白折腾。本机是移动动态 NAT，出口 IP 会变（11-10~11-13 是 117.185.175.186，11-15 起是 117.185.173.213），白名单只认精确 IPv4、不认网段，长期稳定要换固定公网 IP 的机器。

**新闻类的三条硬规矩**（2026-11-16 新增）：

1. **两个以上独立信源**才能写进正文。厂商单方面说法要标「这是他们自己的说法」，不能当事实。
2. **数字回一手原文核**。中文媒体的「暴涨 300%」「节省 90% 成本」几乎都缺口径，查不到出处就写「官方未公布具体数字」。
3. **不做预测、不替读者判断股价**。新闻稿的结论只能是「这件事改变了什么」，不是「所以某某要涨」。

**新闻类的结构跟论文不一样**：论文从场景切入，新闻从「刚发生的那个动作」切入（谁在什么时候发布了什么）。然后按「发生了什么 → 为什么现在发生 → 对普通人意味着什么 → 还没确认的部分」四段走。不要写成时间线大事记。

**新闻选题的价值判断**：问自己「这条消息三个月后还有意义吗」。只有当天热度、没有结构性变化的（比如某榜单换了个名次），不写。

**论文类放开到全领域后，选题门槛反而更高**：不是「顶会」就写，而是「现象能否被一张对比图说清」。视觉、多模态类论文的图通常比具身智能更好看，但也更容易变成炫技演示。判据：能不能在开头 300 字内讲出让非从业者「哦原来是这样」的反差。

**跨领域术语要现查现解释**：具身智能领域的术语我已经很熟，但语言模型、扩散生成、AI for Science 里的 MoE、RLHF、上下文窗口、蒸馏、量化等，每个都得给生活化类比，别直接搬论文原话。

**仓库自带的宽幅图表，先按手机宽度算一遍字号再用**（2026-11-17，laya）：
- 正文显示宽度约 345px。源图 963 宽的速度柱状图缩下去是大图 0.36 倍，10–15px 的标签只剩 4–5px，糊成一片；1196×1876 的纵向语言点图更糟，语言代码完全读不出。
- 判据：**源图宽 ≈ 345 × 1.6~1.9，图内字号 ≥ 20px**。达不到就别硬塞，自己重画一张（560 宽的柱状图缩放 0.62，14px 标签落地约 9px，能看）。
- 四宫格合成图要么按面板裁开，要么整张不用；裁切后必须量一遍坐标轴有没有被切掉——速度面板连着两次裁掉了横轴刻度和 `questions per call`。

**项目类稿件，"作者自己承认的缺陷"是最强的素材**：laya 的 README 单开一节 Honest limits，里面有「零样本 0.362，低于全押一个答案的 0.461」「高棉语准确率 0 而置信度 95.2%」「act_probability 还没有可用信号，AUROC 0.30」这类话。直接引用比自己去论证局限更有说服力，也顺手满足了「还缺什么」的必写段。

**"用几十行数据喂一遍"的对照实验最适合讲清楚"它到底会不会"**：laya 的 fit 例子是 60 行留 20 行，团队分类 0.600→0.900，同时「紧急程度」那道题因为打平被系统拒绝接管，接管后的 20 条又全被标成「要复核」。一个例子里同时有提升、有拒绝、有余量不足，比单给一个准确率数字信息量大得多。

**"不生成所以快"这类机制解释，要落到"答"这个动作上**：把「大模型答一个词要先写一个词」和「打分不产生序列」并排放，读者不需要知道 transformer 就能懂。对照图比流程图更适合这种二选一的对立。

**新闻稿最省力的结构，是「同一周里两件相反的事」**（2026-11-17，ChatGPT 钱包）：OpenAI 11-13 把付款这一环修通，美联航 11-11 把门关上。两件事各自单独写都只是公告，并排放在一起才有张力。找 C 类选题时，先问「这一周有没有人在反着走」。

**官方公告可能一张图都没有**：OpenAI 的 Wallet 帖子是纯文字（抓下来 5.6KB 正文，零 `<img>`），og:image 也取不到（curl 直连返回 403，r.jina.ai 只给正文）。这种情况下 C 类只能全自制图，别去扒 The Verge 的「Image: OpenAI」截图——那是媒体转载，图注写不清出处。4 张全自制反而是这套稿最干净的做法。

**数字的参照系要换成「人能干的事」**：3.2 亿单里 504 单，写百分比（0.00016%）读者没感觉，写「每 63 万单里有一单是 AI 下的」立刻懂。换算时先算除数，再挑一个生活里出现过的量级。

**flow 图的 sub 别混日期和说明**：「2025 年秋，即时结账」在 180px 宽的节点里会被折成「即时/结账」。日期单独放在 sub、细节交给图注和正文，三节点全单行。

**compare 图两栏要点数不等会留白**：右侧 4 条、左侧 3 条时，左边卡片下面空出一大块。宁可砍掉第 4 条（本次是 Booking，且它只有一家英文小站做信源，本来也不该进正文），也要让两边齐平。

**视觉类论文要先算「显示宽度」，不要先算字符数**（2026-11-18，Know When to Zoom）：这类论文的图多是窄长折线/柱状，源图 236pt 宽缩到手机 345px 后字号只剩 4 到 7px。判据仍是「源图宽 ≈ 345×1.6~1.9」。图 3 那种 15 行的榜单图直接弃用，改用论文 Table 2 自己画一张 7 行的柱状图，标签从 18px 提到 20px、画布从 700 收到 640，手机上才读得出来。

**「模型不会说自己看不清」比任何跑分都好讲**：同一批「切块答对、整图答错」的题，Claude 只有 5%–9% 是自信地答错，Gemini 是 43%–48%。这一组对照不需要任何背景知识，是这篇稿子真正的钩子，应该放在全文最靠前的位置之一。

**PIL 手绘柱状图里，虚线空槽要留足行高**：用虚线框表示「整张拒收」时，ROW_H 46 会让框底压到下一行的柱子；改到 54、框高 20 才干净。另外横向图的左侧标签一旦超过 7 个字符，就拆成「厂商 + 型号」两行，比缩字号有效。

**手机 Agent 类项目的真正门槛不在模型，在权限**（2026-11-19，Mika）：它借用安卓「无线调试」启动内置助手，另开一块看不见的后台屏点 App，所以不占主屏；代价是用户得亲手走完开发者选项、USB 调试、无线调试、配对码这一串，官方「遇到问题」表有二十行。写这类稿，把「装它比用它难」单列一节，比夸它多能干更可信。

**「不适配任何 App」是最好的机制解释**：Mika 没有微信、美团的接口，靠读界面结构 + 自带文字识别 + 看图模型三板斧。这句话一出来，读者立刻懂「为什么它什么 App 都能碰」，比讲权限模型省一百字。

**默认「询问」模式只拦花钱那一步，是全文最反直觉的事实**：发消息、发帖、删内容都不问。这类「安全开关的真实边界」比宣称的「很安全」有信息量，凡是写 Agent 产品都要去文档里核一遍默认值。

**Beta 项目的局限素材在 issue 里最全**：本次四条故障（荣耀 Magic7 锁屏识别失败、微信小程序自带 OCR 读不到字、锁屏后定时任务不触发、执行中误开别的 App）全部来自 issue 标题，比自己评测更有说服力。注意别引用已被新版本修掉的（换机备份在 v0.1.48 已补）。

**「两个方向相反的数字」是财经新闻最好的入口**（2026-11-20，Anthropic 上市）：账面净亏 807 亿，经营现金流却是正的 39 亿。一句「怎么可能」就能把读者拉住，然后解释可转债的公允价值变动——估值越涨，账上亏得越多，现金一分没动。这类反差不需要任何金融背景。

**估值先问「按哪套股本算」**：同一家公司、同一时刻，完全稀释口径和已发行股份口径能差三成，媒体报出来的「1.5 万亿」和「2 万亿」指的不是同一件事。写这类稿要先把口径摊开，这本身就是给读者的工具。

**官方公告页可能一张图都没有**：Anthropic 的定价公告正文零 `<img>`，og:image 只是 logo 占位。这时用「官方页面截图 + 自制图」，但截图必须在 520 窄视口下截——桌面 1000 宽缩到手机 345 宽，正文只剩 7px。

**「还没确认」要写成判断尺子，不是免责声明**：把三个版本的算力承诺（9000 亿 / 6570 亿 / 5180 亿）、两套估值口径、以及「史上最大」这个媒体说法并列出来，读者才知道下次看到类似数字该问什么。

**「它不是在做 X，是在做 Y」是最省字的机制解释**（2026-11-21，作者归属）：AI 文本检测器量特征、答「像不像机器」；这篇让模型从记忆里认人、答「这是谁」。一句话把两件事分开，后面所有数字才有位置放。凡是「能力被误读成另一种能力」的论文，都先找这个对照。

**arXiv HTML 的图有两种，别只 grep `<img>`**：这篇 17 张图里只有 2 张是 `<img>`，其余全是 `<object type="image/svg+xml" data="xxx.svg">`。取图地址是 `https://arxiv.org/html/<id>v1/<data>`，下下来用无头 Chrome 渲染成 PNG 再裁。

**多面板图要先算「显示字号」再决定是否整幅用**：Fig 6 两面板在 900 宽渲染时字约 28px，缩到手机 345 宽只剩 11px；Fig 4 五面板更糟。这种图只取一个面板（本次取「私密评审」那块 905×315），或者干脆按论文数据自己重画一张。

**论文里的「口径」要交代，别直接抄摘要**：摘要写 39% 公开评审认出作者，但 1,559 篇里有 770 篇被判 AI 参与、那批只有 1%–4%；39% 是剩下 789 篇的口径。把这件事写出来，读者才不会被一个数带跑。

**作者披露的利益相关是现成的局限素材**：这篇的 12 位作者里有一位来自 Pangram Labs，而 Pangram 既是拿来对比的检测器，又是筛「哪些稿子算 AI 参与」的工具。写进「没说的地方」比写「未来可期」有用得多。

**B 类稿的「分数」是最好的机制解释**（2026-11-22，Craft Anything）：这类工具最容易写成功能罗列，救回来的是「分数怎么算」——三档宽度截图、布局与像素结构两路平均、连自变部分先剔掉。把打分方法讲清楚，读者自然懂「93% 只代表像，不代表能用」。凡工具带评分，先把尺子拆开讲。

**官方文档里的「没验过」是最硬的局限素材**：docs/STATUS.md 是一张 471 行的表，每行写「做到什么程度、凭什么这么说」，还留着「API key 那条路没跑过一次真实构建」「Codex 适配器没在真实安装上验证」。直接引用比自己评测可信，也顺手填掉「还缺什么」必写段。

**截图先算显示字号再裁**：仓库 README 截图是 2160 宽（2x 渲染），整幅压到 345px 后正文只剩 7px。做法是按「逻辑区域 ×2」裁一条窄栏（本次 432×646 的右栏、430×280 的卡片），缩到 345 后正好 1:1，字全清楚。

**make_diagram 出的图要裁白边再用**：画布 780 宽里左右各 56px 是白底，与公众号白底混在一起，看起来「图变小了」。按非白像素 bbox 裁掉（留 18px），显示宽度不变、字号实际放大 13%。

**flow 四节点的副标题只能 5 字**：780/1.52 时每节点 134px，「AI 照着重写」会折成「AI 照着／重写」，改成「照着重写」才单行。宁可省掉主语，也别让它折行。

**「同一个模型、换个位置」是最省力的科普角度**（2026-11-23，决策模型三种角色）：JEV 当执行者 42.9%，当老师教出 82.9%，中间没换模型、没换参数。这类反差不需要任何背景知识就能看懂，比讲架构好一百倍。凡遇到「评测口径决定结论」的论文，先找这种同一对象两种身份的数字。

**讲概率分布要给一个具体现场**：光说「它把 63.8% 的概率给了容易那一步」读者没画面。写成「手里拿着冷杯子，人就站在桌边，A 直接放下、B 去微波炉」之后，那句话才立得住。诊断类实验（多少个状态、怎么筛的）也要给数：116 个现场、66 个任务。

**两个数字对比时要说清是不是同一个口径**：0.36 与 0.05 都是「组内里程碑减空转」，只是问法不同；不点明的话，读者会以为是两组实验。同理 82.9% 与 86.8% 是两个任务子集，正文必须分开交代。
