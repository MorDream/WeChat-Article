## 经验沉淀

**标题**：带具体动作或数字的比抽象概念好。"穿过一堆杂物"胜过"全身视觉语言导航"。

**结构**：场景开头 → 旧方法的局限 → 这篇怎么改的 → 数据和训练怎么来 → 结果 → 反直觉发现 → 局限 → 收尾。这个骨架读者反馈最好。

**配图**：论文原图负责"可信"，自制示意图负责"看懂"。一张自制图讲清一个机制，别塞三个。

**数字**：所有数字必须有出处。不确定就写"论文未提及"，不要圆。

**长度**：2500 字左右最舒服，超过 3500 字完读率明显下降。

**篇幅硬限制**：微信 `draft/add` 的 content 字段上限 2 万字符，而每个 `<p>` 带 112 字符的行内样式。2600 汉字配 5 张图大约 1.85 万字符，已接近天花板；再长要拆篇，或把相邻短段合并（用单换行 `<br>` 代替空行分段）。

**栏目**：论文 / 项目两类隔期交替。2026-11-02 起，论文（TANGO）→ 项目（StarVLA）→ 论文（Rho）→ 项目（RPent）→ 论文（Ψ₀）→ 项目（Microduck）→ 论文（ABot-M0）→ 项目（Jumper）→ 论文（VT-WM）→ 项目（gpu-unlock）→ 论文（RoboColosseum）→ 项目（HALO）→ 论文（GAP）→ 项目（RoboScript）→ 论文（BEHAVIOR 2026）。下一篇回到项目类，`待写` 已空。

**「官方开源 + 论文」是最好的项目选题**：HALO 这类仓库自带 arXiv，论文原图负责可信、README 负责"到底开源了什么"，两类素材都有。比纯仓库稿好写，比纯论文稿好找图。

**代码开源 ≠ 能复现**：先翻 README 的「Weights and data」段和残留的 `TODO(release)` 注释。HALO 明确写"没有训练好的生成器检查点，也没有数据集"，这句话直接撑起整段局限，比任何客套话都有说服力。

**二手数字只用来判断热度，不用来写稿**：中文媒体把 91% 转得到处都是，但"链式任务 70%/50%""5 次失败 3 次头转开"这些只有原文有，也是全文最有价值的部分。热度看媒体，数字看原文。

**标题落在"第一次"上最容易懂**：「没见过一间真房子，它就自己找了张椅子坐下」比"零样本全身运动迁移"好一百倍。


**预印本要标清楚**：VT-WM 只有 arXiv 版 + OpenReview 投稿记录，项目页与论文都没写录用会议。正文用「状态：预印本」如实交代，别为了贴「顶会论文」栏目硬安一个会议。

**相对涨幅 vs 百分点**：论文爱写 "up to 35% higher"，实际是 69%→93% 的相对涨幅，绝对差 24 个百分点。这类地方必须拆开讲，否则读者会算出 104%。

**项目稿的局限好写**：成熟仓库基本都会在 PROJECT_GUIDE / README 的 status 段里自陈"哪一步还没做完"，直接引用比论文的局限段省事，也更容易写出信任感。

**"只迁移改法"是很好的科普角度**：GAP 不搬"怎么弹"，只搬"偏了往哪边拧"。这类"换掉迁移对象"的思路，比讲架构好讲得多，读者也能直接类比到自己的学习经验（教练纠正的不是动作本身，而是偏差方向）。

**arXiv HTML 的数字会被 LaTeX 复制成"1616""3.33"...**：`1616 actuated finger joints` 其实是 16，`4.44.4` 其实是 4.4，`77 min` 其实是 7 min。读到相邻重复的数字要警惕，别照抄。

**"相对提升"必须当场换算**：GAP 真机写 +16%/23%/3.6%，全是相对自己；0.759 涨 23% 是 0.935，绝对差 17.6 个点。不换算，读者会算成 0.98。

**arXiv 没生成 HTML 版时，从 PDF 取图**：RoboScript 的 `/html/2611.12885v1` 返回 404（No HTML for the source），但 PDF 里的图是矢量+位图混排。用 pymupdf `get_pixmap(clip=Rect(...), dpi=210)` 按坐标裁切，图内文字 1:1 清晰，比截图干净，也不会有缩放糊边。

**密集信息图要按面板拆**：Fig. 1 整幅 1395×643，压到手机 390 宽后字全糊；只取右半的 (c) 榜单面板（630×694）后，每一行的数字都能读。判据是「裁完的宽高比接近 2:3 或 1:1」而不是 2.2:1 的横条。

**「仓库 + 论文」是项目稿最优解，但热度要如实交代**：本次仓库 1 周 67 星，不算爆款，热度只靠「arXiv 当日新稿 + 第三方转载」。这类选题可以写，但汇报时必须说明「不热」，别把冷门说成热门。

**compare 图的 note 会与图注重复**：图底部的小字说明和正文图注写的是同一句话，删掉 note 只留图注，观感更干净。

**「名次掉了、分数涨了」是极好的科普角度**：榜单名次是相对的，题目变难、对手变强都会让名次下滑。写这类稿必须把「名次」和「水平」拆成两件事讲，否则读者会误读成退步。BEHAVIOR 2026 那篇正是靠这个反差立住的。

**挑战赛稿要先确认是哪一名**：标题写 "Our Solution for the 2026 XXX Challenge" 很可能是第 9 名而不是冠军。BEHAVIOR 2026 这篇摘要第一句就是 "We placed 9th"，差点按冠军事写。凡涉及名次，先在 abs 页搜 "place" / "rank"。

**同一篇里要区分「哪个模型」的分数**：BEHAVIOR 稿里 0.392 是纯学习策略，0.446 是含 14 件外包的公开提交，27.3% 又是后者口径。混着写读者会算不明白，必须在句子里点明主体。

**定性判断也要对着图表核**：初稿写「爆米花是最简单的一档任务」，但 Figure 11 里它排在中上，最简单的其实是「捡垃圾」和「装调制解调器」。难度这种形容词最容易凭感觉写错。
