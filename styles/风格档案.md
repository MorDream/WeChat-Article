# 写作风格档案

这个文件是文稿的验收标准。写稿前读一遍，写完对照末尾的检查清单过一遍。

## 目标读者

**对 AI 有兴趣，但不是从业者。**

画像：会用 ChatGPT、听说过「大模型」，可能刷到过机器狗视频，但不知道 VLA 是什么、没读过论文、分不清「参数量」和「训练数据量」。

他们点开文章的原因通常是：标题讲了一件具体的事（机器人挤过杂物堆），而不是因为这篇文章解读了某篇论文。

**判断标准**：如果一个句子需要读者先知道另一个术语才能读懂，就改写。

## 文风

**句子**

- 短句为主，一句话不超过 40 字
- 一段只讲一件事，超过 5 行就拆
- 少用「值得注意的是」「综上所述」「不难发现」这类过渡词
- 可以用「你」「我们」，像跟人聊天，不用「笔者」

**小标题**

口语化，能让读者预判这一节讲什么，最好带一点情绪或反常识。

- 好：「把机器人当成地图上的一个点，是错的」
- 好：「大模型 0.5 秒才想一次，机器人怎么站得稳」
- 差：「方法概述」「实验分析」「结论」

**开头**

从一个具体场景切入，让读者在脑子里看到画面。500 字内必须出现「这篇论文做了一件什么事」。

禁止用「随着人工智能的快速发展」「近年来，XX 领域取得了长足进步」这类套话开场。

**结尾**

不复述全文，给一个能带走的判断或一句让人记住的话。

## 术语处理（最重要）

**每个术语第一次出现时，就地解释，一句话，用生活里的东西类比。**

不要把这些解释堆到文末做名词表——读者不会翻回去看。

已经验证有效的写法：

| 术语 | 处理方式 |
|---|---|
| 具身智能 | 就是「有身体的 AI」。ChatGPT 只输出文字，具身智能要输出动作 |
| VLA | 视觉 + 语言 + 动作，看着画面、听着人话、直接吐出动作数字 |
| 零样本 | 没在这个环境里练过，第一次见就直接上 |
| 29 个自由度 | 能单独转动的关节有 29 个 |
| 仿真 | 电脑里造的三维假世界，有物理引擎，撞到桌子会真的被挡住 |
| A* | 游戏里点一下地面，角色自己绕开障碍走过去，用的就是这类算法 |
| 动作跟踪器 | 机器人的「小脑」：大脑说手抬到那儿，小脑负责让手稳稳到那儿 |
| 扩散模型 | 先给一团噪声，一步步去噪得到结果。AI 画图是这么干的，这里是生成动作 |
| 消融实验 | 「拆零件」测试：把某部分拿掉，看性能掉多少 |
| SPL | 把成功率和路径长度绑在一起算，绕得越远分数越低 |

**允许直接用的词**：机器人、摄像头、服务器、开源、论文、模型、成功率、碰撞。

**必须解释的词**：所有英文缩写、所有带「度/场/空间/流形」的专业名词、所有算法名。

实在绕不过去的术语，用「说人话就是……」「换句话说……」接一句白话。

## 数字处理

**每个关键数字后面要告诉读者这个数意味着什么。**

反面：「成功率 43.75%」——读者会想「才四成，这模型不行啊」。
正面：「这类任务四成左右就已经是当前最强水平了」——先给坐标系，再给数字。

数字必须来自论文原文。没写的地方就说「论文未提及」，不推测、不估算、不用「大约」。

## 图片

- **论文原图**：从 arXiv HTML 版直接下载原始文件，不用截图，不用 AI 生成冒充
- **自制示意图**：用 `make_diagram.py` 生成，每篇至少 1 张，用来解释机制而不是装饰
- 每张图下面写清是什么，论文原图要标注「论文原图」
- 长文（3000 字以上）图片间隔不超过 600 字，读者需要喘气的地方

## 必须写的一段

**局限或不足。** 至少 200 字，要具体，不能写成「未来可期」的客套话。

好的局限：没开源、只用纯视觉没讨论逆光玻璃、SPL 偏低偏保守、仿真场景比真实仓库干净。

## 检查清单

交稿前逐条过：

- [ ] 开头 3 行内有画面感，没有「随着……的发展」
- [ ] 每个英文缩写第一次出现都解释了
- [ ] 没有一句话超过 40 字
- [ ] 每个关键数字都给了参照系
- [ ] 至少有一处指出这篇工作的局限
- [ ] 自制示意图至少 1 张，且是用来讲机制的
- [ ] 小标题能让人预判内容，不是「方法」「结果」
- [ ] 结尾没有复述全文
- [ ] 通读一遍，没有需要读者往回翻才能懂的句子
